**Added by v4.3** — the AI-infra completeness pass (2026-10-10). An audit against what AI-infra roles actually probe found two kinds of gap: sources missing for work the plan already commits to, and topics absent entirely. The governing rule for everything below: **a reading that produces no claim is a boundary answer, not signal** — so each item is tagged for which it is. Three tiers.

**Tier 1 — sources for builds already planned (~2–3 evenings total).** The post-engine tier had drills and builds with no primary sources behind them, which is the exact combination that produces "I built it and can't defend why."

- **Thakur, Rabenseifner & Gropp, *Optimization of Collective Communication Operations in MPICH* (2005)** — the alpha–beta cost model behind Tier A item 1's crossover. Without it the fitted terms have no lineage, and "why those two terms" is the drill.
- **Gibiansky, *Bringing HPC Techniques to Deep Learning* (Baidu, 2017)** — ring all-reduce, the algorithm that item implements, and the source of the ring-not-tree argument.
- **Shoeybi et al., *Megatron-LM* (2019)** — tensor parallelism for transformers: column- and row-parallel sharding of MLP and attention, and the origin of "two all-reduces per layer" that Tier B item 6's drills assume you can explain.
- **Frantar et al., *GPTQ* (2022)** and **Lin et al., *AWQ* (2023)** — post-training quantization, for Tier B item 4. Both are named as interview topics in [`15-phase-5-docs.md`](15-phase-5-docs.md)'s industry-context Q&A with no source behind them.
- **Leviathan, Kalman & Matias, *Fast Inference from Transformers via Speculative Decoding* (2023)** — Tier B item 5. The paper states the batch-1 framing that makes the item's finding (the gain decaying as batching rises) predictable rather than surprising.
- **Dao et al., *FlashAttention* (2022)** — required if A5 takes the fused-attention branch, and the cleanest second example of the IO-awareness reasoning A4 teaches.
- **Ainslie et al., *GQA* (2023)** — Tier A item 2's grouped-query attention, and the query-to-KV-head ratio that turns the KV arithmetic into the standard story.
- **Karpathy, `llm.c` (source read)** — GPT-2 in C/CUDA, no dependencies: the closest existing artifact to step G's build. llama.cpp stays the reference for KV-cache and sampling craft; llm.c is what a minimal forward pass gets diffed against.

**Tier 2 — two builds this pass adds (both chained off interfaces the plan already specifies).**

- **Prefix caching** — Phase 6 rung 2b ([`16-phase-6-scheduler.md`](16-phase-6-scheduler.md)). Chains off step G's KV allocator interface; no new seam. Measurable hit rate and TTFT delta against a shared-prefix workload. Reading: vLLM's prefix-caching / block-hashing docs and the SGLang RadixAttention paper (Zheng et al., 2023) — the latter for *why a radix tree rather than a hash map*, which is the design question the build forces.
- **Triton GEMM** — step A optional rung ([`20-ai-extension.md`](20-ai-extension.md)). The same GEMM as the CUDA kernel, diffed against both your CUDA and cuBLAS — a three-way comparison in the plan's existing idiom. Reading: the Triton docs and its GEMM tutorial. It is a language, not a textbook; the tutorial is the whole reading.

**Tier 3 — vocabulary with sources (~1 week of evenings, boundary answers only, no build claims).** Every item here lands in the industry-context Q&A ([`15-phase-5-docs.md`](15-phase-5-docs.md)) with a boundary line, capped the way the existing know-only list is. This tier exists because these are standard probes and "never heard of it" is a worse answer than "I know what it solves, here is why this project does not have it."

- **Training-side distributed:** FSDP/ZeRO (Rajbhandari et al., *ZeRO*, 2019; PyTorch FSDP docs), pipeline parallelism (Huang et al., *GPipe*, 2019), mixed precision (Micikevicius et al., 2017), checkpointing and fault tolerance (Megatron/DeepSpeed docs). One paragraph each; the honest boundary is the project's own non-goal.
- **Tensor cores and architecture-specific paths:** CUTLASS docs, and the Hopper TMA + `wgmma` sections of the CUDA C Programming Guide. This also sharpens A5's cuBLAS gap attribution, which already names tensor cores as one candidate cause.
- **Multi-LoRA serving:** S-LoRA (Sheng et al., 2023) and Punica (Chen et al., 2023). Boundary: this project deliberately serves one model ([`00-master.md`](00-master.md) non-goals).
- **Structured / constrained decoding:** Willard & Louf, *Efficient Guided Generation* (2023), plus the `xgrammar` or `outlines` docs. A real production topic with no analogue here — state it as a gap, not a build.
- **KV cache offloading:** FlexGen (Sheng et al., 2023) and vLLM's offloading docs. Boundary: this project's KV budget is device-memory-only by design.
- **GPU sharing and multi-tenancy:** MIG and MPS documentation, time-slicing. Boundary: one process, one device.
- **Evaluation harnesses:** `lm-evaluation-harness`. Boundary: this project's evaluation is a token-for-token correctness gate, not a benchmark suite.

**Not added, and the reasons stand:** Kubernetes / Ray / OpenTelemetry / operators (tooling, not findings — [`20-ai-extension.md`](20-ai-extension.md)); multi-model serving (conflicts with the non-goal); distillation, pruning, and mixture-of-experts (frontier-*model* vocabulary, not infrastructure work); serving a real 7B (the architecture-breadth argument at Tier A item 2 already closes the same gap with engineering). Training-infrastructure as a *built* door remains out of scope — Tier 3 is the boundary answer for it, not a plan branch.
